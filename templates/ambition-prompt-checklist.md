# AI 野心升級檢查表（Ambition Prompt Checklist）

> 來源：Felix Rieseberg〈[How to be more ambitious: A tutorial for humans with models](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)〉；分析筆記見 [`notes/2026-10-24-felix-rieseberg-how-to-be-more-ambitious.md`](../notes/2026-10-24-felix-rieseberg-how-to-be-more-ambitious.md)（任務 `T-20261024-01`）。
>
> **用途**：派工給 Agent（或寫進 `notes/` 的任務）之前，用這張表把指令從「同一件事做更快」拉到「更高、更深、更廣、可被外部驗證」。
>
> **不適用**：改錯字、查單一事實、一行設定修改等小事。野心不是每次必跑的強制流程；中大型任務、或原本要「開會討論」的事才拿出來用。
>
> **停損**：拉高野心後，仍必須寫出 DoD 與停損條件（時間上限、迭代次數上限、需維護者同意的動作），避免無限迭代。

---

## 使用方式

1. 先照平常習慣寫下原始指令（改寫前）。
2. 依序走過下面四個面向，每勾一項就把對應的要求補進指令。
3. 用「深度元提示」收尾：請模型先回答面向二的四問，再**重寫你的指令**，你確認後才執行。
4. 最後檢查面向四：指令裡的每個「完成」都能被模型以外的東西驗證。

---

## 面向一：目標背後的目標（高度／為什麼只做到這裡？）

不交辦步驟，直接索要「結果」。判斷訣竅：如果這件事最後還需要「開會討論」，代表高度不夠。

- [ ] 我寫的是「步驟」（修這個、查這個）還是「結果」（讓它不再壞、讓人能據此做決定）？已改寫成結果。
- [ ] 問過「做完之後，維護者／團隊要拿它做什麼決定？」並把那個決定寫進指令。
- [ ] 問過「為什麼只做到這裡？」：若再往上一層目標也在 Agent 能力與權限範圍內，就一併納入；若不在，明寫邊界。
- [ ] 產出能直接被下一步使用（例如可勾選清單、可執行指令、可貼進筆記的表格），不需要人再轉譯一次。

## 面向二：深度四問（用專家的工具與原始材料，而不是專家的口吻）

不要叫 AI「扮演專家」（只會換用語）；要求它使用專家**實際的工具、方法與原始材料**。

- [ ] **① 如果這已經完美了，下一步是什麼？** 把「下一步」中能順手做完的部分併入本次範圍，其餘記為後續任務。
- [ ] **② 什麼事做一次就能讓後面十件事變簡單？** 找出可重用的產物（範本、腳本、對照表），優先做它。
- [ ] **③ 我現在避開不談的那個問題是什麼？** 把最不舒服、最可能推翻結論的問題明寫進指令，要求正面回答。
- [ ] **④ 如果拿給最挑剔的同行看，他第一個會挑哪裡？** 把那個挑剔點寫成驗收條件之一。
- [ ] 指定「從最原始的材料開始」：官方文件、原始碼、條款原文、實際輸出，而非二手轉述或搜尋摘要。
- [ ] 指定「具體方法與工具」：要跑哪個指令、讀哪個檔、比對哪份資料，而不是「請仔細分析」。

## 面向三：廣度動詞化（名詞換動詞，組夢幻團隊）

把任務的名詞換成動詞，再問「各領域的人實際會『做』什麼」。跨領域視角現在請得起。

- [ ] 把任務名詞改寫成動詞句（例：「一份報告」→「判斷哪些宣稱可以相信」）。
- [ ] 列出 **5 個**能帶來不同視角的領域，各寫一句「這個領域的人會怎麼解同一個問題」。
- [ ] 每個領域寫的是**實際動作**（查證數字、找最脆弱的假設、比對版本差異），不是角色扮演的口吻。
- [ ] 從 5 個視角中挑出至少 1 個原本沒想到的動作，納入本次指令。

> 廣度提示範本：「這個任務如果用動詞描述，是在『做』什麼？列出 5 個能帶來獨特視角的領域，說明每個領域的專家實際會做哪些分析，然後依序執行。」

## 面向四：外部裁判（拒絕讓 AI 自己打分數）

除了你和模型之外，什麼東西能客觀證明結果正確？

- [ ] 每一條驗收標準都綁定可執行的檢查：測試、腳本、`Select-String` 計數、`verify_inbox.py`、原始資料比對、外部工具輸出。
- [ ] 指令中明寫「回報時附上檢查指令與實際輸出」，沒有輸出就不算完成。
- [ ] 刪掉所有只能靠模型自評的標準（「品質良好」「分析完整」「足夠詳盡」）。
- [ ] 若結論依賴外部來源，要求附上來源連結與查閱日期，讓第三方可重查。
- [ ] 寫明停損：超過幾次迭代或哪種動作（付費、註冊、部署、碰其他 repo）要先停下來問維護者。

## 實測：真實任務「改寫前／改寫後」對照

- **挑選任務**：`T-20261024-05`（來源：[`notes/2026-10-24-ai-influencer-ig-story-chatgpt-heygen-elevenlabs.md`](../notes/2026-10-24-ai-influencer-ig-story-chatgpt-heygen-elevenlabs.md)）
- **挑選理由**：屬於「查證型」任務，最容易停在「查到就好」的速度層級；且下游 `T-20261024-06`（AI 人物合規檢查清單）要依它的結果開工，適合檢驗高度與「做一次讓後面變簡單」。

### 改寫前

> 查證影片的三項宣稱：IG 標示 AI 生成是否不被降權、ElevenLabs 與 HeyGen 的肖像與聲音授權範圍、兩工具現行費用。產出 `docs/ai-influencer-claims-check.md`，三項宣稱各一列，每列含官方來源連結、查閱日期與判定。

（即任務原始描述的濃縮版；本身已有 DoD，但停在「查完填表」。）

### 套用檢查表

| 面向 | 檢查發現 | 補進指令的要求 |
|---|---|---|
| 高度 | 真正的目標不是「三列表格」，而是讓 `T-20261024-06` 能直接據此寫合規清單、讓維護者判斷「這套做法能不能用」 | 每列多一欄「對合規清單的影響」，結尾給一行「可用／有條件可用／不建議」的總判斷 |
| 深度 ① 完美後的下一步 | 下一步就是 `T-20261024-06` | 每個判定順帶標出它對應合規清單的哪個類別（AI 揭露、被攝者同意、聲音授權、商用、平台政策） |
| 深度 ② 做一次省十次 | 條款與價格會變，每次重查都從零開始 | 記下每個官方頁面的確切 URL、頁面標題與查閱日期，供日後重查直接比對 |
| 深度 ③ 避開的問題 | 「沒找到降權說明」不等於「不會降權」 | 判定只用「官方證實／官方未提及／與官方矛盾」，禁止把「未提及」寫成「證實」 |
| 深度 ④ 挑剔同行 | 會挑「你看的是哪一版條款、哪個地區的價格」 | 價格註明幣別、方案名稱與地區；條款註明生效或更新日期 |
| 廣度：動詞化 | 「一份查證文件」→「判斷三項宣稱各自能不能信」 | — |
| 廣度：5 領域 | 法務：讀條款原文找肖像／聲音／商用限制條文；平台政策分析：找 Meta 對 AI 標示與分發的官方說明；財務：把費用換算成每月實際成本；資安與隱私：確認上傳的照片與聲音樣本如何被保存與再利用；新聞查核：把影片原話和官方原文逐句對照 | 採納「資安與隱私」視角：每個工具補一行資料保存／再利用條款；採納「新聞查核」視角：每列附影片原宣稱的引述 |
| 外部裁判 | 原 DoD 只數連結數量，無法判斷連結是否為官方來源 | 連結網域必須是 Meta／Instagram、HeyGen、ElevenLabs 官方網域；不註冊、不付費，遇到需登入才看得到的內容就標「官方未公開」並停下 |

### 改寫後

> **目標**：判斷影片中三項宣稱各自能不能信，讓 `T-20261024-06` 可以直接依此撰寫 AI 人物合規檢查清單，並讓維護者一眼看出這套做法「可用／有條件可用／不建議」。
>
> **材料與方法**：只讀 Meta／Instagram、HeyGen、ElevenLabs 官方網域的說明頁、服務條款與價格頁（不註冊、不付費、不登入）。每項宣稱先引述影片原話，再逐句對照官方原文。
>
> **產出**：`docs/ai-influencer-claims-check.md`，三項宣稱各一列，欄位為：影片原宣稱、官方來源 URL、頁面標題、查閱日期、判定（只能是「官方證實／官方未提及／與官方矛盾」）、對合規清單的影響類別。另附：
> - 兩工具各一行「上傳素材的保存與再利用條款」摘要；
> - 價格註明方案名稱、幣別與地區；
> - 文末一行總判斷。
>
> **驗收（外部裁判）**：
> 1. `Select-String -Pattern 'https://'` 計數至少 4，且所有連結網域屬於上述三家官方網域；
> 2. `Select-String -Pattern '官方證實|官方未提及|與官方矛盾'` 至少 3 筆，且不得出現其他判定字樣；
> 3. 回報時貼出上述兩條指令的實際輸出。
>
> **停損**：任何需要登入、註冊或付費才能看到的內容，標記「官方未公開」並停止深挖，不自行推測。

### 前後差異

| 比較項 | 改寫前 | 改寫後 |
|---|---|---|
| 產出用途 | 一張查證表 | 查證表＋可直接餵給 `T-20261024-06` 的類別對應＋總判斷 |
| 判定可信度 | 只要求判定，未禁止把「未提及」當證實 | 判定字樣封閉為三選一，並逐句對照原話 |
| 可重查性 | 有連結與日期 | 再加頁面標題、方案、幣別、地區，日後可直接比對變動 |
| 外部裁判 | 只數連結數量 | 連結網域限定官方＋判定字樣計數＋回報須附輸出 |
| 新增視角 | 無 | 資安與隱私（素材保存條款）、新聞查核（原話引述） |
| 停損 | 不註冊、不付費 | 再加「需登入即標記並停止」，避免推測 |

**結論**：改寫前的指令已有基本 DoD，但只停在速度層級的「查完填表」；套用檢查表後，高度（服務下游任務與決策）、深度（原始條款、封閉判定）、廣度（隱私與查核視角）與外部裁判（網域限定與字樣計數）四個面向都有具體增量，且每項增量都能用指令驗證。
