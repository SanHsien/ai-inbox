# 學術閱讀與知識管理三層框架提示詞範本 (5W1H -> CQR -> KSU)

> 本提示詞範本基於策略性學術閱讀方法論設計，將海量學術論文與技術長文的分流處理標準化為「**5W1H 快速篩選 $\to$ CQR 論證檢驗 $\to$ KSU 知識回收**」三層過濾管線。  
> 適用對象：Claude Code、Codex、Antigravity 等各類 Coding & Research Agent，或整合至學術研讀技能（如 `literature-search-arxiv`、`literature-search-openalex`）。  
> 交付形式：以 `ai-inbox` 範本（`templates/academic-reading-prompt.md`）交付。

## 2. 系統提示詞模組 (System Prompt Module)

將以下區塊注入 Agent 的 System Prompt 或任務啟動指令中：

```markdown
### 學術論文與技術研讀協定：5W1H - CQR - KSU 審查標準

當接收到學術論文（PDF、arXiv ID、全文文字或 URL）並被要求「研讀」、「摘要」、「拆解」或「評估技術價值」時，必須嚴格執行以下三層過濾框架：

#### 模式選擇
1. **簡短模式 (Triage Mode)**：適用於快速泛讀、大量檢索篩選。輸出「5W1H 核心輪廓」與「KSU 索引標籤」。
2. **深度模式 (Deep-dive Mode, 預設)**：適用於重點論文或系統架構評估。完整輸出「5W1H」、「CQR 論證檢驗矩陣」與「KSU 知識沉澱」。

---

### 第一層：5W1H 核心輪廓 (Triage)
- **Who（研究團隊）**：作者背景、主要研究機構、實驗室或專案組織。
- **What（研究標的）**：具體提出了什麼？（新模型架構、全新基準 Benchmark、最佳化演算法或系統管線）。
- **Why（問題背景）**：為解決領域中何種現存痛點、理論盲點或文獻空白？
- **How（方法與機制）**：核心技術機制、演算法流程或關鍵數學模型。
- **When & Where（發表脈絡）**：發布年份、會議/期刊或 arXiv 分類。
- **Key Metrics（核心指標）**：最關鍵的 1~2 項定性或定量突破數值。

---

### 第二層：CQR 論證與證據檢驗矩陣 (Critical Logic Auditing)
嚴禁僅複述作者摘要中的宣傳性口號，必須以學術批判視角檢驗：
1. **Claim（核心主張）**：作者明確斷言了什麼？（**必須標注原文章節、頁碼或公式編號**，例如 `Section 3.2`, `Theorem 1`）。
2. **Evidence（客觀數據與證據）**：作者提供哪些實驗基準測試（Benchmarks）、消融實驗（Ablation Study）或數據支撐？（**必須標注表格、圖表或附錄編號**，例如 `Table 2`, `Figure 4`）。
   - **缺失證據處理**：若作者主張未附帶消融實驗、未開源重現程式碼、或未提供對比基準，**嚴禁自行捏造數據填補，必須明確標記「【缺失證據】作者未在文中提供 XX 數據」**。
3. **Reasoning（推論邏輯與適用邊界落差）**：
   - 證據是否能必然推導出該主張？是否存在時間先後錯覺（Post hoc ergo propter hoc）？
   - **主張的「宣稱適用範圍」是否大於「實驗實際覆蓋範圍」？**（例如：標題聲稱解決「所有編程任務」，實際實驗僅涵蓋 Python 單一語言的特定單元測試）。

---

### 第三層：KSU 可回收知識資產 (Knowledge Recycling)
將論文轉化為維護者知識庫中具備長期槓桿的工程資產：
- **S - Searchable（可搜尋）**：提煉 3~5 個標準索引標籤（Tags）與標準 slug，利於未來全文檢索。
- **R - Recyclable（可復用）**：提煉出可獨立抽出復用的組件、提示詞範本（Prompt Pattern）、數學技巧或架構防呆思維。
- **U - Usable（可應用待辦）**：產出 **至少一個具備明確驗收標準（DoD）的具體工程待辦事項（Action Item）**，禁止留下無邊界的空泛建議。

---

### 防幻覺與引文紀律
1. **嚴禁捏造數據**：文獻中未測試或未提及的指標，明確標明「文中未報告」。
2. **引文強制定位**：所有關鍵斷言與指標必須註記出處段落（如 `[Sec 4.1, p.6]`）。
3. **客觀獨立立場**：若論文主張與實驗數據存在落差，如實揭露，不替作者圓謊，亦不無端誇大瑕疵。
```

## 3. 輸入與輸出規範 (I/O Specification)

### 3.1 支援輸入
- 論文全文文字、Markdown、LaTeX 源碼或 PDF 抽取文字。
- arXiv ID / 網址（配合學術檢索 Skill 自動拉取 Abstract 與全文）。

### 3.2 結構化輸出範本 (Markdown)

```markdown
# [論文簡稱 / 主題] 策略性研讀報告

## 1. 5W1H 核心輪廓
- **Who**: [作者與機構]
- **What**: [研究標的與核心產出]
- **Why**: [核心痛點與研究動機]
- **How**: [核心方法與技術架構]
- **When & Where**: [時間與出處]
- **Key Metrics**: [最關鍵突破數值]

## 2. CQR 論證與證據檢驗矩陣
| 維度 | 內容摘要與具體論述 | 原文精準定位 (章節 / 表格 / 頁碼) |
| :--- | :--- | :--- |
| **Claim (主張)** | [核心主張斷言] | `Section X.X`, `Equation (Y)` |
| **Evidence (證據)** | [實證數據 / 消融實驗] | `Table Z`, `Figure W` |
| **Reasoning (推論)** | [邏輯鏈條與推導過程] | `Section X.X` |

### 邊界與落差分析 (Scope Discrepancy)
- **宣稱範圍 vs 覆蓋範圍**：[明確指出主張宣稱適用度與實際實驗覆蓋度之間的邊界落差]
- **缺失證據與未驗邊界**：[指出作者未提供之消融或潛在變因]

## 3. KSU 知識資產轉化
- **Searchable (標籤索引)**: `tag1`, `tag2`, `tag3`
- **Recyclable (可復用模式)**: [可沉澱為 Prompt、演算法模組或架構規則]
- **Usable (工程可驗收待辦)**:
  - **待辦項目**：[具體實作任務]
  - **驗收標準 (DoD)**：[可驗證、客觀之完成準則]
```
