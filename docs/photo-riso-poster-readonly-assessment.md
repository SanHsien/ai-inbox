## 2. 原檔實際規定了什麼

```text
照片 ──(宿主模型看圖)──▶ 文字事實：數量、間距、遮擋、方向、色溫、2–3 個色彩角色
  │                          │
  └─(可選 EXIF 拍攝日期)─────┤
文字主題 ─(模型自行設想少量檔案資訊)─┤
                             ▼
             四段式純文字提示詞 ──▶ 生圖工具（不附原圖）──▶ 海報
                             ▲                                │
                             └── 自檢不合格：加強措辭重生成一次 ┘
```

- 構圖目標：65–85% 空紙、單一視覺群聚占 10–25% 且偏離中心、2–3 色油墨、紙色跟隨照片大面積色溫。這些是寫進提示詞的**目標**，原檔沒有提供量測方法或實測數據。
- 三檔抽象度：faithful、standard（預設）、minimal。人物一律是小型匿名剪影、動物是無五官剪影、不畫臉。
- 排印承載事實：數量標記、日期行、天氣或時段短註、2–4 個英文單字的短語（可疊成 2–4 行）、檔案編號。
- 交付時要附上實際送出的提示詞與「證據落在哪裡」的說明。這一點有利於事後查核。

筆記需要修正的三處（本任務不改筆記，列給整合者）：短語是 2–4 個單字而非 2–4 行短詩；「每項排印都是觀測證據」只適用照片分支；「零腳本所以無越權風險、已通過靜態安全檢視」的說法過強，見下節。

## 3. 提示詞安全風險

純 Markdown 沒有可執行檔，但它是寫給宿主模型的指令，宿主有什麼工具權限，它就能驅動什麼。原檔 frontmatter 只有 `name` 與 `description`，沒有限制可用工具。

| 項目 | 原檔怎麼寫 | 風險 | 與本機規則的關係 |
| --- | --- | --- | --- |
| 自主工具呼叫 | 要求全程自主、不提問；只有生圖工具不可用才停，而且禁止改用程式繪圖 | 觸發後不經確認就呼叫生圖，直接消耗額度；使用者沒有機會先看提示詞 | 與「需求有多解先問」「token 就是錢」衝突。禁止用程式繪圖這條反而是好的停止條件，不會偷換做法 |
| 重生成 | 交付前自檢一次；油墨太淡、文字亂碼或版面塌成滿版場景就重生成一次 | 上限明確（每次請求最多兩次生圖），但合格與否由模型自判，沒有使用者同意這一步 | 可接受的上限；若採納應改成「先回報不合格項，再問要不要重生成」 |
| 照片資料流 | 鎖定檔案路徑、由宿主模型看圖；原圖不附給生圖工具 | 照片仍然會送到宿主模型的服務端；不附原圖只減少生圖工具端的影像暴露，不等於照片不離開本機 | 私人照片是否可送，取決於宿主模型的資料條款，本次未查 |
| EXIF | 讀得到拍攝日期就用，並舉 exiftool 或 PIL 為例；讀不到就省略日期，不可杜撰 | 這兩種工具的預設輸出包含 GPS 座標、裝置型號等欄位，會整段進入對話內容；原檔沒有要求只取日期欄位。自主模式下，模型也可能為了讀 EXIF 而嘗試安裝工具（原檔沒有這樣要求，這是推論） | 日期一旦印上海報，就跟著成品被分享出去 |
| 地名 | 高信心辨識出地點才寫，否則省略 | 「高信心」由模型自判；寫錯是虛構資訊，寫對是位置揭露 | 若採納，建議預設不寫地名 |
| 文字主題的虛構資訊 | 明文要求為主題設想少量檔案資訊（數量、季節、天氣感） | 「不可杜撰日期」只寫在照片分支；排印系統卻一律列出日期行，文字主題分支沒有禁止，模型可能自行編日期 | 成品看起來像檔案紀錄，容易被誤認為真實資料 |
| 檔案編號 | 固定詞彙 `ARCHIVE NNN` 或 `NO. NNN` | 兩個分支的編號都沒有來源事實，與同檔「每個排印事實都要能追溯到來源」的自檢條件互相矛盾 | 應視為裝飾元素，不可當成證據 |
| 照片中的文字 | 沒有處理 | 照片裡的招牌、螢幕或紙條文字會被宿主模型讀到，可能夾帶指令（間接提示詞注入）。這是推論，原檔沒有對應防護 | 適用外部內容零信任規則 |
| README 與 SKILL.md 不一致 | SKILL.md 只把「像一点／more faithful」對應到 faithful 抽象度（第 20 行），沒有個體相似度的規則，且第 39 行仍要求動物無五官、人物匿名；README 第 34–42 行把 likeness 當成 faithful 以外的另一件事，所以兩者不一致。另外 README 第 63 行自稱 no bundled assets，但 repo 有 26 個圖檔 | 使用者照 README 操作時，行為沒有規格可依；個體相似度不被保證 | 筆記不應寫成支援個體辨識 |
| 安裝方式 | README 第 47 行的安裝指令是用 `git clone` 把整個 repo 放進 `~/.codex/skills/photo-riso-poster` | 沒有固定版本，之後更新會直接改變模型收到的指令；也會帶入約 17 MB 圖檔 | 與「採納前先過安全檢查」衝突 |

已做的靜態檢查與範圍：SKILL.md 全文沒有外連網址、沒有 HTML 註解；SKILL.md、README.md、LICENSE 三檔沒有零寬或雙向控制字元（以 Python 掃描 U+200B–200F、U+202A–202E、U+2060–2064、U+FEFF 與 tag 字元區，結果皆為 0）。人工逐行閱讀沒有看到要求外傳資料、讀取憑證或關閉沙盒的指令。這只涵蓋固定 commit 的三個文字檔，不是完整安全認證。

## 6. 採納裁決

**不採納原 skill；不安裝、不收錄進 `SanHsien/agent-assets`（私有）。方法列為設計參考。**

理由：

1. 沒有具體需求。目前沒有待辦的海報或攝影視覺工作，生圖額度與驗收時間沒有對應的產出。
2. 原檔照搬會違反本機規則：全程自主不提問、自判後自動重生成、文字主題可編造資訊、EXIF 讀取範圍沒有限制。
3. 安全檢查還沒做，依規定不能安裝。
4. 風格規則本身（留白、油墨、紙色）只是提示詞目標，沒有量測證據支持「比直接風格化好」。

重新考慮的條件：出現具體的海報需求，且維護者同意花生圖額度。屆時不安裝原檔，改寫一份自有版本，並做到：

- 保留 MIT 版權聲明與授權全文，註明改寫自固定 commit。
- 拿掉「全程自主不提問」；送出生圖前先顯示提示詞。
- 重生成改為回報不合格項後由使用者決定。
- EXIF 改為使用者明確要求才讀，且只取拍攝日期一個欄位；預設不寫地名。
- 文字主題分支明文禁止日期行；設想出來的數量、季節標示為創作資訊，不稱為證據。
- 檔案編號標示為裝飾。
- 先通過 SkillSpector 與技能包安全檢查器。

| 檢查項 | 怎麼判 | 通過條件 |
